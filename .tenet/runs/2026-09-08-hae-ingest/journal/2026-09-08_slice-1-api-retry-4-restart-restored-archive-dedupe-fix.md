# slice-1-api retry #4: restart-restored archive dedupe fix (code_critic product_bug)

## Findings

- **bug**: code_critic product_bug vs commit 943f342 — the POST /api/ingest duplicate gate (main.py:172) consulted only `ArchiveStore.seen()` (in-memory index). After a service restart the index is empty, so re-posting identical bytes returned `{"outcome":"stored"}` and bumped `stats.stored` instead of the spec-required idempotent `{"outcome":"duplicate"}` (spec failure table: "Duplicate payload (same sha256) → 200 idempotent; no reprocessing"; anti-scenario 1: no double counts ever).
- **reproduction (dynamic, pre-fix)**: fresh `TestClient(main_mod.app)` against the same `ARCHIVE_ROOT` — first POST → `stored`; second app instance ("restart") re-post of identical bytes → `stored`, stats `stored=1, duplicate=0`. BUG CONFIRMED assertion fired.
- **fix**: `src/health_db/main.py` — duplicate gate now `store.seen(content_sha) or store.find_by_sha256(content_sha) is not None`. `find_by_sha256` consults the in-memory index then the persistent disk-backed archive via the cold-start scan (restored by prior retry 64a680a: content-indexes every non-quarantine JSON, retry on transient read errors), so a restart-restored archive yields `outcome:"duplicate"` with no second copy. Docstring pipeline step 4 updated to state the persistent-index gate. All prior verified work kept: signature fix, quarantine sidecars, 5 automation-header tests, 8-key shape assertions, 20/20 prior slice-1 acceptance tests.
- **regression tests**: `TestRestartRestoredArchiveDedupes` in tests/acceptance/slice_1_ingest.py — (1) `test_repost_identical_bytes_after_restart_is_duplicate`: fresh TestClient against the same ARCHIVE_ROOT; re-post → `outcome="duplicate"`, stats `duplicate=1, stored=0, received=1`; exactly 1 archive file, byte-identical, path equals the pre-restart `archive_path`; then a *different* payload still stores normally (stored=1/duplicate=1). (2) `test_repost_of_foreign_named_archived_payload_is_duplicate`: hand-placed non-conventional filename still dedupes via the disk scan. (3) `test_new_payload_after_restart_stores_normally`: the disk-backed gate must not over-dedupe fresh bytes.
